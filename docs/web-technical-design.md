# Water Fill｜满一点
## 技术方案 A · 离线单文件 HTML MVP

**技术方案 v1.0｜产品基线 PRD v0.2｜2026-09-14**

透明试接 → 不透明正式挑战 → 立即显示最终等级。

本方案把三关离线游戏拆成可实现的模块、数值契约、构建规则及验收门槛。最终给玩家的运行文件只有 `water-fill-mvp.html`；开发源码、自动化测试和本技术文档不属于运行依赖。

| 项目 | 约定 |
|---|---|
| 产品范围 | 3 关、每关透明试接与不透明正式关；每次只关一次 |
| 运行环境 | 明确通过验收的本地 JavaScript / WebGL 浏览器；不承诺 iPhone 文件预览 |
| 技术路线 | TypeScript + Three.js + 原生 DOM；构建为内联经典脚本 |
| 配套测试 | 03-web-test-cases.xlsx；共同测试编号 C-*，Web 专项 W-* |
| 复用关系 | 同一 game-core、关卡及渲染器供后续 iOS 本地宿主使用 |
| 完成状态 | 设计与测试用例，非已完成游戏；所有产品测试均待执行 |

采用 v0.2 的默认三关、首次一遍试接、S/A/B/C/D/F 及 F 也可进入下一关作为实施基线。参数变更须同时更新配置版本、金标数据及用例，不在代码里静默改规则。[D0]

**阅读顺序：** 先确认第 1–5 节规则与数值，再实现第 6–9 节画面、离线和存档；第 10–12 节用于拆任务及验收。与另一份方案冲突时，共享规则以本方案及 PRD 为准，平台能力以 iOS 方案为准。

## 01｜架构与关键决定

### 1.1 不从演示文件直接堆功能

沿用已认可的画面方向，但把场景脚本中的“总出水量最多一杯”“满杯自动成功停水”移出正式核心。两阶段都不能补水；重试创建新尝试，而不是恢复旧水流。没有独立自由练习、账号、联网、星级或分数页面。

### 1.2 一套核心，三种消费者

`输入 → GameController → game-core → 快照 / 结果 / 事件`

`快照 → Three.js 渲染器；结果 → DOM 界面 / 存档；事件 → 音频 / 平台触感适配器`

| 模块 | 职责与边界 |
|---|---|
| core | 状态、计时、积分、水量账目、关停计划、判级；不引用 DOM 或 Three.js |
| content | 三关配置、容器剖面、量化表、固定随机种子、schema 校验 |
| render | 容器、水柱、波纹、溢流；只消费数据，不另算等级 |
| ui | 阶段、按钮、反馈、记录回顾；唯一输入分发入口 |
| platform-web | Web Audio、存档、安全降级、页面生命周期 |
| build / tests | 内联产物、资源审计、核心金标、离线与视觉回归 |

Three.js 选择经过画面回归的一版并写死在 lockfile，禁止依赖范围漂移。当前官方 WebGLRenderer 使用 WebGL 2；选此路线时把 WebGL 2 能力检查作为启动门槛，不把旧 Demo 的兼容范围直接搬过来。[S1]

### 1.3 范围与回退

不用 React、全局状态框架、物理插件、Service Worker 或运行期 WASM 解码器。固定场景的近似水足以支撑玩法，先降低装饰复杂度，不降低规则准确性。源码可通过构建工具生成单文件，不要求玩家安装任何开发工具。

配置编译时输出 `rulesVersion、levelVersion、configHash、coreBuildHash`。两阶段使用相同 configHash；材质、画质、音量和阶段标签不进入游戏配置哈希。iOS 必须复用同一核心与配置产物，禁止 Swift 再实现一套评分。

## 02｜状态、输入及重新开始

### 2.1 产品状态与视觉状态分开

| 状态 | 允许操作 / 转移 |
|---|---|
| INIT | 初始化、检查资源与存档；成功进入第一关 TRIAL_READY |
| TRIAL_READY | 开始试接；若已有有效试接，也可进入正式关 |
| PREPARING(stage) | 统一 400ms 准备；忽略提前关闭，不缓存输入 |
| TRIAL_RUN | 自动出水；首次有效关闭生成试接反馈，不登记正式等级 |
| TRIAL_REVIEW | 再试 / 进入正式；有效自动溢出也算一次已完成试接 |
| FORMAL_TRANSITION | 清空 → 材质变不透明；不出水、不接收开始 |
| FORMAL_READY | 明确开始正式关；或返回透明试接 |
| FORMAL_RUN | 自动出水；关闭 / 首次实际溢出 / 30s 安全上限产生结果 |
| RESULT | 再挑战 / 透明试接 / 下一关；F 也可继续 |
| INTERRUPTED | 未结算尝试作废，回到原阶段待机，不补发成绩 |

视觉状态 `POURING / CLOSING / TAIL / IDLE` 可在 TRIAL_REVIEW 或 RESULT 后继续。离开旧结果时取消旧视听事件，不等待尾水动画结束才允许重试。[D0 §05]

### 2.2 输入契约

关水由场景主体或底部按钮的 `pointerdown` 触发；顶部导航、设置、结果按钮不冒泡到场景关水。只处理 primary pointer，过滤鼠标非左键、重复 keydown 和多指。Space / Enter 首次按下及无障碍激活走同一 `dispatch(CLOSE)`。

每次尝试记录 `attemptId、inputConsumed、activePointerIds`。接受关闭后先同步锁定 inputConsumed，再生成计划。开始与关闭按事件身份隔离，不能通过同一手势连跳两态。

结果控件须同时满足：原手势已结束，等级首帧出现已满 250ms，并且操作来自新的手势。键盘须释放原按键。超时 / 自动溢出虽无关闭手指，也执行 250ms 保护。

### 2.3 重试与阶段切换

统一 `disposeAttempt()` 取消动画任务、音频节点与平台事件，清空 V/A/O/S、计划、波纹、相位和输入标志；递增 generation，再创建新 attemptId。旧回调必须带旧 generation，收到后一律丢弃。透明→正式的材质转场结束后进入待机，不能自动开始计分。

## 03｜时间与整数水量：确定性的基础

### 3.1 单位与守恒

容量统一记为 `C = 1,000,000 u`；u 是百万分之一杯，不是毫升。每关真实毫升数仍用于几何和流量换算。账目为已发射 S、杯内 V、空中 A、累计溢出 O；始终满足 `S = V + A + O`。计划内未发射 B 不提前加入 S 或 V。

时间使用相对出水起点的整数微秒。固定 120Hz 网格取 `tickUs(k)=floor(k×1,000,000/120)`，不能反复累加 8,333μs 导致长期漂移。400ms 准备期不属于出水时间。

流量及线性启动 / 关闭采用有理数积分；关键累计量使用 BigInt 分子分母计算，最终 u 值在安全范围内转 Number。渲染浮点不反向写核心。JSON 与原生桥只传安全整数和字符串，不直接序列化 BigInt。

### 3.2 不逐帧取整

定义精确累计发射函数 `E(t)`，一次推进新增水量为 `floor(E(t1))−floor(E(t0))`。关闭计划沿用 tClose 时的精确累计余数，不能先丢掉余数，再从零积分尾水。这样分段方式不同不会累计丢水。

空中水采用固定发射网格的水包而非 GPU 粒子。每包拥有确定的发射时刻与整数 amountU；下落和液面相交按固定步及统一事件顺序转账。几何查询表和落地阈值用固定精度整数，表面装饰波纹不参与落地或溢出判定。子步关闭只截断所在发射段，不改变此前水包划分。

### 3.3 输入不等下一渲染帧

规范化 event.timeStamp 到单调时间轴，在输入处理器内推进到准确的关闭时刻，拆分所在逻辑步，然后封存计划。rAF 只决定何时展示，不决定何时关闭。调试回放把事件预先排队，按时间戳而非批次顺序消费。

保留短检查点处理尚未结算的迟到输入；若无法按原时间重放，按技术中断处理，不偷偷使用当前时刻。已确认结果不被后来的重复 / 过期输入改写。严重主线程阻塞（初始阈值 250ms）在判级前优先中断，并记录原因；现场输入延迟与逻辑回放一致性是两种不同测试。

同一微秒事件顺序冻结为：发射与落地账目 → 首次溢出锁定 → 关闭输入 → 安全超时。恰好满而未溢出不失败。游戏配置、音频、画质均不得改变此顺序。

## 04｜ClosingPlan 与即时最终等级

### 4.1 一次生成，不可反复修正

`closeAt(t)` 先推进当前账目，再冻结剩余线性关阀发射与两滴尾水的时刻、整数总量和量化余数。计划只创建一次；计划生成后不再读取运行时随机数、材质或质量档。

令关闭时杯内为 V、空中为 A、既有溢出为 O、尚未发射计划水量为 B：

`finalRetained = min(C, V + A + B)`

`finalSpilled = O + max(0, V + A + B − C)`

判级先检查失败原因 / finalSpilled，再依次比较 `990000、970000、900000、750000`。全部使用整数，不比较显示百分比。Ofinal > 0 即 F，包括只有 1u 的溢出；1000000u、无溢出是 S。[D0 §04]

### 4.2 显示值和正在下落的水不是同一个字段

同步锁输入 → 核心生成计划和 Result → 立即更新 DOM 等级 → 异步存档与反馈 → 按原计划继续渲染余水。不能把 finalRetained 写入当前 V；否则关水后液面会瞬间跳到最终位置。

全部水落地后断言 `A=0、V=finalRetained、O=finalSpilled`。预测 F 时允许先显示 F、再看到真实溢出；不能为配合结果提前制造溢流水。其后即使检测到首次实际溢出，也不能重算或截短已经冻结的玩家关停计划。

无人关水时，首次实际溢出才创建自动关停计划并锁 F。30s 安全超时同样 F，但原因写 `no_close_timeout`，不能伪称已溢出。技术中断不生成 F。

### 4.3 可执行金标

| 输入（C=1000000u） | 最终结果 |
|---|---|
| V=962000，A=15000，B=10000，O=0 | Vfinal=987000，Ofinal=0，A级 |
| V=985000，A=12000，B=7000，O=0 | Vfinal=1000000，Ofinal=4000，F级 |
| V=999999，A=0，B=1，O=0 | 恰好一杯，S级 |
| V=999999，A=0，B=2，O=0 | 只溢出1u，F级 |

附带 JSON 包含全部等级边界 ±1u、已有溢出、空杯和超时。校验脚本只验证这些规格样本，不是游戏实现通过测试的证明。

本公式仅适用于静止、单腔、全部入杯、无外部流失、关闭后无新操作的 MVP。未来加移动容器或随机飞溅流失时必须重新设计，不能沿用预测承诺。

## 05｜三关参数、几何及时间窗口

### 5.1 待调优的初始工程值

| 参数 | 第一杯 L01 | 收口 L02 | 最后两滴 L03 |
|---|---|---|---|
| 容量 | 250mL | 220mL | 320mL |
| 稳态流量 | 25mL/s | 26mL/s | 26mL/s |
| 关阀线性时间 | 80ms | 80ms | 180ms |
| 尾滴 | 无 | 无 | 关阀完成后100/180ms，各400u |
| 容器 | 直筒剖面 | 上窄下宽剖面 | 宽矮剖面 |

建议所有关采用 60ms 线性启动，作为 PRD 未指定细节的工程初始值；试接和正式严格一致。最大喷嘴到杯底落差先取 0.22m、向下初速 1.5m/s，重力 9.8m/s²，用于压住关水后的视觉尾段。只有正式配置与模型校验完成后这些值才冻结。

### 5.2 不把 C/Q 当作最优关闭时刻

在已经进入稳态且没有漏水的本模型中，最终总入水量为：

`W = Q×(tClose − startup/2 + closeDuration/2) + tailVolume`

据上述建议启动值得到连续量的解析校验区间（秒，以源头开始出水为0）：

| 关卡 | S级关闭时间近似区间 | 区间宽度 |
|---|---|---|
| L01 | 9.890000–9.990000 | 100.000ms |
| L02 | 8.366923–8.451538 | 84.615ms |
| L03 | 12.114769–12.237846 | 123.077ms |

这是数学参考，不是实机测试结果。最终用整数核心先 1ms 扫描、再 1μs 精化边界；每关实际连续 S 窗口须≥80ms。若改启动曲线、尾滴或容量，重新生成金标，禁止修改预期值来掩盖实现偏差。

飞行时间会改变当下液面和可见余水，但在“全部水最终入杯”的前提下不额外改变总入水量；不能既将 A 计入，又再次扣掉一段飞行补偿。

### 5.3 同一剖面生成模型和容量表

以轴对称内壁剖面 radius(height) 生成容器内外壁及分段圆台体积，构建严格单调 V(h)。用相同数据反查液面高度，禁止美术模型与评分容量各写一份。L03 最后一滴发射最晚在关闭后360ms；上述落差对应约108ms最大飞行，预期视觉尾段约468ms，再以实际配置验证≤650ms目标。

## 06｜水的渲染与不透明防泄露

### 6.1 混合表现，不做完整流体求解

杯中水为体积映射的水体网格与局部波纹；水柱为采样源头历史的变形网格；细滴用实例化网格或复用粒子池。水柱从喷嘴向下断开，不能整段消失。尾滴量由核心规定，粒子数量可以随画质改变，水量不能改变。

透明试接的液面受落水事件驱动凹陷、环形波纹及衰减。容量判定只用体积，近杯缘约束波峰和装饰飞溅，不允许不计分的水看起来流到杯外。正式已确定 F 的等级与溢流水可先后出现，但溢流水只能由实际 O 的增长驱动。

### 6.2 正式阶段从渲染源头阻止偷看

两阶段使用相同固定正交侧向镜头，杯口内面处于不可俯视角度；不开放轨道控制器、陀螺仪或自由缩放。正式杯壁 opacity=1、transparent=false、depthTest/depthWrite=true，关闭玻璃 transmission。

正式渲染根本不提交杯内水面、内部气泡、内部落点及内部水柱；从喷嘴到杯口的外段仍可见，长度只由喷嘴与杯口决定，不能随液面缩短。内部水对象不得进入反射、阴影、焦散、后处理、轮廓或拾取调试通道。全部关闭内部绘制仅是显示策略，核心 V/A/O 及自然声音仍照常运行。

### 6.3 相同镜头与低画质必须同时达标

透明→不透明时先清空水和尾滴，再过渡材质。正式开始前内层 draw list 已关闭。改变窗口只调整画幅，不提高镜头角度；极小窗口无法完整展示时在开局前提示，不偷偷切到俯视。

不透明泄露测试用同一时间、同一外部水流，将内部 V 依次置于0/25/50/75/90/99%进行离屏比较；测试构建冻结装饰种子。正式画面受水位影响的像素应为0，跨设备截图仅允许平台光栅差异，不与另一种设备基线直接比较。透明阶段同样实验应有明显差异，防止把水渲染整体删掉“通过”测试。

正式结算保持不透明。用户若要重新观察水位，只能返回透明试接，不提供结果揭杯动画。

## 07｜离线打包与资源审计

### 7.1 构建路线

开发使用 TypeScript、多文件 import 和固定依赖；发布用 esbuild 将入口递归 bundle 为 IIFE，关闭 splitting 和 external，再把 JS、CSS、关卡及许可证嵌入 HTML。esbuild 支持 bundle 与 IIFE，这不等于任意动态路径都能自动内联；产物还必须审计。[S2]

| 构建项 | 必须设置 / 检查 |
|---|---|
| 入口 | 一个 browser entry；平台依赖注入，不在运行时下载 |
| 脚本 | 经典内联 script；无外部 src、动态 import 或旁文件 |
| 模型 / 贴图 | 程序生成；内置 typed array / data URI；禁止网络 loader |
| 声音 | 预生成程序噪声、内置采样；不使用音频 CDN |
| 字体 / 图标 | 系统字体、内联SVG；无远程字体 |
| 编码 | UTF-8；正确转义脚本中的结束标签，保留许可证 |
| 产物 | 只有 water-fill-mvp.html；源码映射仅内部留存 |

编译环境安装依赖可能联网，与玩家运行无需联网是两件事。离线运行不能以“之前联网缓存过”“旁边有一个 assets 文件夹”或“启动本地服务器”替代。[D0 §07]

### 7.2 防意外请求

构建阶段解析 HTML 标签、CSS url/import、JS 外部依赖和 sourcemap 声明；许可证中的文本网址不等于资源请求，不能用全文件搜 http 的粗糙规则误报。

建议生成 meta CSP：默认拒绝外部来源，script-src 使用生成后的内联脚本哈希；connect-src、worker-src、frame-src、object-src 均为 none；img/media 仅允许确有需要的 data/blob；style-src 为内联样式预留授权。不得以关闭浏览器安全机制解决兼容问题。

运行验收同时开启请求日志与出站拦截；即使请求被 CSP 拦住，也说明代码尝试了外联，须排查。要覆盖请求创建接口、外部标签和用户导航，不只检查是否有成功的 HTTP 200。

### 7.3 版本与体积预算

HTML 内记录只读版本信息和许可证，构建侧记录 SHA-256。初始体积预算≤5MiB（工程目标，非 PRD 原始指标）；超过时先分析纹理、字体和音频，不外置资源破坏交付契约。初次支持矩阵冻结前不承诺所有浏览器或手机文件管理器可运行。

## 08｜界面、动效与声音

### 8.1 界面实现

采用语义化 DOM button、阶段文字与一个 canvas。等级由大字和短评呈现，不显示实时水量、倒数计时、分数或星级。读屏标签只描述当前操作，不把内部满杯度写进 aria 属性、隐藏DOM或按钮状态。

Web MVP 默认、低画质、减少动效、声音四项策略独立。正式关按钮外观不随水量变动；首屏不自动接水，准备期400ms到达出水起点才启动源头曲线。

### 8.2 短动效使用统一取消令牌

透明→正式过渡可采用250ms；重试复位200ms；等级字立即可见，再做200ms轻收束。减少动效时使用≤100ms淡入或直接状态切换，但400ms准备、真实关阀及尾滴完全不变。所有动画均绑定 attemptId / generation，不能通过 animationend 决定物理时钟。

接水时不弹设置、不提供暂停。退出则按中断处理；结果出现后用户可在保护期结束时立即跳转，旧尾水在内存中被销毁，不转移到新尝试。

### 8.3 程序声音与因果

启动时只建立数据，首次用户开始手势中创建 / resume AudioContext；Promise 拒绝时显示非阻塞静音提示，不延后开始或关闭。浏览器可能限制未交互的有声自动播放，因此不能把成功播放作为开局的前提。[S3]

使用一次生成的带限噪声 buffer 作为流水源，滤波与混合随同一流量 / 水位快照平滑变化。阀门与滴水使用短包络音；音量不以突然跳变代替结果反馈。准备音频数据只做一次，重试不重新创建大量长期节点。

关水只按关停曲线淡出源头声音，落水与尾滴继续；结果短音不盖住尾滴。试接用中性反馈，不播放正式S奖励。自然水声可以随水位变化，透明与正式必须共享同一模型；不能额外加入“快到99%”提示音。

无音频设备、静音或 AudioContext 被系统暂停时仍可完成三关。返回前台只在新的明确操作中恢复必要声音，不补播旧局队列。

## 09｜存档、生命周期与故障

### 9.1 存档契约

`SaveV1` 保存 schemaVersion、revision、三关 trialCompleted、最高正式 grade、latestResult、settings 和已处理结果ID摘要。等级顺序 S>A>B>C>D>F；同级不暗比时间 / 水量。试接仅更新完成标记，不改正式记录。

localStorage 在 file URL 下没有统一持久化保证，访问也可能被策略拒绝。初始化 try/catch 做读写探针；不可用则用内存适配器，并提示关闭后可能丢失。[S4] 不调用 localStorage.clear() 删除其他内容，仅操作带前缀的本游戏键。

主档/备份均含版本与校验值，写入新档成功后再提升 revision；错误保留最近有效档。未知等级、超范围关卡、NaN、未知 schema 不直接信任。改文件名或路径后不承诺找到旧存档；这不影响游戏本身离线可运行。

### 9.2 正常中断与已出结果分开

| 异常节点 | 处理 |
|---|---|
| PREPARING / RUN 离开前台 | 取消本局；不出等级、不计试接完成；回原阶段待机 |
| RESULT / REVIEW 后离开 | 已生成的结果/试接标记保留；取消尾水及声音 |
| WebGL 上下文丢失 | 未出结果先中断；有限重建一次；失败给重新打开入口 |
| 长帧超预算 | 未结算局技术中断；不丢弃时间继续假接水 |
| 数据损坏 / 存储满 | 恢复有效档或内存继续；显示保存限制 |
| ClosingPlan核对失败 | 阻塞缺陷；冻结新开局并报技术错误，不静默改已显示等级 |

清空 progress 需二次确认，只清游戏进度与教程标记，保留声音、画质和减少动效偏好。结果写入按 attemptId 幂等；重复渲染、visibilitychange 或双击不能多次更新纪录。

### 9.3 调试边界

QA 构建允许注入固定时间、读核心快照和导出有限本地日志；生产构建静态移除注入与改级入口。纯客户端源码仍可被持有文件的人修改，不宣称防作弊。日志不上传网络、不含身份信息，产物不含GitHub令牌或签名材料。

## 10｜性能预算与测试架构

### 10.1 可测量目标

| 项目 | 初始门槛与测法 |
|---|---|
| 按钮/阀门首反馈 | 输入处理器收事件→首个可见变化，P95≤50ms |
| 等级首帧 | 有效关闭→可读等级首帧，P95≤100ms；与存档耗时解耦 |
| 帧表现 | 默认目标60fps，低档30fps；记录中位数/P95/P99，不只均值 |
| 冷启动 | 本地导航开始→可点击首关待机，20次，P95≤3s |
| 稳定性 | 20分钟且≥100次重试；无崩溃、旧事件、持续对象增长 |
| 时窗 | 三关扫描S连续窗口≥80ms；不靠人手碰边界 |
| 一致性 | 同输入于30/60/120帧调度下最终整数账目和等级完全一致 |

首帧用高帧率相机或可校准呈现追踪核对；一次 rAF 回调发生不等于像素已经显示。软件日志只度量调度延迟，不能宣称测到了完整触摸硬件延迟。

静态资源复用，水包/粒子使用对象池；透明效果、反射和波纹分级。只在待机切质量档；高/低质量的核心回放结果必须一致。WebGL模拟器或软件GPU只用于逻辑与回归，不能替代目标设备性能证据。

### 10.2 分层自动化

核心：Node 测试直接消费金标JSON、守恒属性测试、随机切段积分和关闭扫描。界面：Playwright 检查阶段、去重、等级与页面生命周期。离线：新配置、先 offline=true、阻断Service Worker，从 file URL 首开，再用整机断网复核。[S5]

Playwright 的 WebKit 不是正式 Safari，移动视口模拟也不等于 iPhone 真机；因此另列 macOS Safari 与 iOS 原生包验收，不把 CI 绿灯当作手机适配完成。[S6]

每次失败保留构建hash、规则hash、随机种子、输入时间线、状态快照、期望/实际和截图。性能测试固定画质、设备温度起点、供电状态与浏览器版本。

## 11｜接口与开发任务

### 11.1 最小核心接口（契约，不是现成实现）

```ts
interface Engine {
  start(level: LevelConfig, stage: 'trial' | 'formal'): void;
  advanceTo(timeUs: number): Snapshot;
  closeAt(timeUs: number, inputId: string): CloseOutcome;
  interrupt(reason: InterruptReason): void;
  snapshot(): Readonly<Snapshot>;
}
interface CloseOutcome {
  plan: Readonly<ClosingPlan>;
  result: Readonly<InternalResult>;
  feedback: readonly FeedbackEvent[];
}
```

`closeAt` 的 trial result 仅内部供校验，UI转换为文字，不写正式纪录。`Snapshot` 分开 actual 水量与 predicted 结果。`FeedbackEvent` 至少含 sessionId、attemptId、generation、eventId、kind、targetTimeUs 和 priority；后续 iOS 只接受白名单事件。

内容校验在开局前执行：容量为正、剖面单调、流量非负、尾滴不早于关闭完成、最长收尾可达、尾滴总量与单位正确。非法配置不能产生一局“永远接不满”的游戏。

### 11.2 可分配的工作包

| 任务 | 交付及完成定义 |
|---|---|
| WEB-01 核心与时钟 | 契约、积分、守恒、关闭计划、等级；共同金标通过 |
| WEB-02 状态与输入 | 两阶段、首次门槛、重试、结果防穿透；C类流程通过 |
| WEB-03 水与遮挡 | 三杯共享几何、液面、尾滴、正式防泄露；视觉回归通过 |
| WEB-04 内容与声音 | 三关配置、S窗口报告、基础声音、静音降级 |
| WEB-05 单文件构建 | HTML唯一运行产物、许可证、哈希、请求审计 |
| WEB-06 存档与异常 | 受限存储、坏档、后台、图形丢失；不影响三关闭环 |
| WEB-07 验收与交接 | 测试执行表、设备记录、性能日志、离线验证录像 |

先做一杯两阶段及ClosingPlan，再扩展三杯；MVP通过后才将同一核心交给iOS宿主。GitHub写入、Pages和商店签名不是任何Web任务的前置依赖。

## 12｜交付门槛、风险与依据

### 12.1 不可豁免的阻塞项

错误等级、预测/实际水量不一致、正式水位泄露、试接与正式参数不同、依赖外网、开始手势误关水、旧事件污染新局，均不能以“只是MVP”豁免。共同用例及Web专项P0全部通过；设备矩阵中任何必测环境的失败都需修复或明确缩小支持范围后重新评审。

配套测试表把“优先级”和“执行状态”分开：当前全部为未执行，不自动勾选通过。规格金标校验仅验证附带测试数据自洽，不代表 Three.js 页面、设备性能或 iOS 能力已验证。

### 12.2 主要风险

| 风险 | 处理 |
|---|---|
| 不透明阶段变成纯猜测 | 确保同题、自然声一致、三关节奏不同；试玩调参数 |
| 数值正确但视觉不可信 | 当前/最终分离，真实落地驱动画面，预测F不提前造水 |
| 升级Three.js改变画面 | 锁版本；颜色管理、透明排序与shader逐项回归 |
| 单文件很大或file受限 | 程序资源+体积审计；支持环境明示，不要求关安全策略 |
| 极端迟到输入 | 记录投递延迟，越界技术中断；不伪造100%硬件确定性 |
