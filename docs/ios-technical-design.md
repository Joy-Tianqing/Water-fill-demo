# Water Fill｜满一点
## 技术方案 B · iOS 动效与原生触感版

**技术方案 v1.0｜产品基线 PRD v0.2｜2026-09-14**

同一杯的答案不变，让“关闭”和“等级落定”更有质感。

本方案交付路径为 Swift 本地宿主、WKWebView 内置游戏、Core Haptics 原生反馈。不是打开在线网页，也不把一个震动调用当作完整 iOS 体验。渲染与游戏规则先复用网页版，原生只负责系统能力和体验协调。

| 项目 | 约定 |
|---|---|
| 玩法与内容 | 与 HTML MVP 同一6关、同一配置与等级阈值 |
| 渲染与判级 | 共享 TypeScript game-core + Three.js；不在Swift重复评分 |
| 原生重点 | 触感时间线、生命周期、可靠本地存档、音频会话与恢复 |
| 安装后网络 | 全部游戏资源本地；首次启动即可离线 |
| 配套测试 | 04-ios-test-cases.xlsx；共同C-*与iOS专项I-* |
| 交付状态 | 技术方案及待执行测试；非已签名安装包或已通过真机验收 |

iOS增强是后续阶段，不能阻塞纯HTML MVP交付。方案与PRD的动效、触感参数均为初始调试值；设备手感、帧率和桥接时延只有真机测量后才可定案。[D0]

**阅读顺序：** 第1–4节确认宿主与桥接；第5–7节实现动效触感；第8–10节处理存档、异常和性能；第11–12节拆任务和验收。

## 01｜路线选择与复用边界

### 1.1 默认方案

`Swift / UIKit容器 → WKWebView(内置HTML) → 共享核心 + Three.js + 游戏DOM`

`Web反馈事件 → 原生Bridge → HapticCoordinator / SaveStore / LifecycleCoordinator`

主游戏按钮与等级仍在Web层同一输入链路中产生，避免“触摸先到Swift，再往返JS，才能判级”。原生不盖住关水热区，不安装与Web竞争的手势识别器。设置可沿用Web界面，原生仅同步系统偏好。

WKWebView提供本地文件加载接口，可指定读取范围；这支持离线宿主，但不证明本游戏已经达到原生引擎级性能。[S1] 采用UIKit是减少宿主重建和手势层次的工程选择，不是说SwiftUI不可用。

### 1.2 为什么不同时做三套引擎

| 路线 | 处理 |
|---|---|
| Swift + WKWebView + Core Haptics | 默认；改动集中于宿主和原生体验 |
| Capacitor本地封装 | 备选；若团队已有工程经验可选，但保留相同桥接与验收契约 |
| Unity / Metal 独立渲染 | 仅在真机门槛无法满足后专项评审；不自动启动重写 |

独立渲染将增加模型、材质、动画、物理表现和跨端一致性的维护成本。先用真实场景测出瓶颈，不能仅凭“封装会慢”或“原生一定流畅”作决定。

### 1.3 必须共享与允许差异

共享：rulesVersion、levelVersion、configHash、整数积分、ClosingPlan、等级、600ms准备、尾滴、试接门槛和继续条件。允许差异：装饰精度、转场、触感、原生存储、系统生命周期。不得让 iOS 多出一种“满杯前提醒”。

iOS编译时将同一核心产物与内容哈希放入Bundle。CI发现Web与iOS内嵌的规则哈希不一致时阻断候选包，不靠手工口头保证版本相同。

## 02｜原生工程、本地资源与启动

### 2.1 模块划分

| Swift模块 | 责任 |
|---|---|
| GameViewController | 持有单一WKWebView、布局、安全区域、宿主错误页 |
| BridgeCoordinator | 协议握手、白名单、序号、回复、attempt与generation过滤 |
| HapticCoordinator | 预热、pattern缓存、调度、取消、引擎重启与降级 |
| SaveStore actor | 存档迁移、原子写入、结果幂等、备份与恢复 |
| LifecycleCoordinator | 前后台、锁屏、Web进程终止、恢复策略 |
| Diagnostics | 本地signpost与有限日志；Release不含调试改级接口 |

### 2.2 启动顺序

原生读取有效存档与设置 → 创建限制好的WKWebView → 注入平台握手对象 → 从Bundle加载内置HTML → Web报告ready及版本 → 校验哈希和协议 → 应用设置与存档 → 开放第一关待机。

本地HTML放独立只读资源目录，`loadFileURL(...allowingReadAccessTo:)`仅授权必需目录，不把用户文档或整个沙盒作为读取根。游戏从不加载远程URL。启动失败保留可读的原生重试页，不让白屏成为唯一状态。[S1]

### 2.3 生命周期与WebView配置

不反复创建WebView来切关；原生容器持有它直到离开整个游戏。禁用页面弹窗和新窗口入口，导航委托仅接受允许的Bundle文档；禁止外链偷偷替换页面。仅靠导航委托不能限制所有子资源，因此继续保留HTML的CSP、产物资源审计与出站测试。

初始支持目标可从iOS 16+、iPhone竖屏开始评审，但这只是部署候选，不是已验收范围。首个可玩包必须冻结具体Xcode/SDK/系统/机型，避免使用测试设备没有的API。无需相机、麦克风、定位、照片、推送或本地网络权限。

启动预算≤3s；声音失败、触感引擎未ready不阻挡进入游戏。签名和分发需用户自己的开发者配置，不在文档或仓库中保存证书私钥。

## 03｜桥接协议：有限、可取消、不在判级关键路径

### 3.1 消息封装

```json
{
  "protocol": 1,
  "sessionId": "boot-uuid",
  "generation": 7,
  "attemptId": "attempt-uuid",
  "messageId": "message-uuid",
  "sequence": 42,
  "type": "feedback.batch",
  "payload": { "events": [] }
}
```

只允许 `hello、attempt.begin、feedback.batch、result.commit、trial.commit、settings.update、clock.ping、attempt.cancel`。数据为JSON安全类型；最大64KiB、事件批次≤16。所有字段枚举/范围校验，未知类型拒绝，不接受任意JS字符串、文件路径、声音URL或任意强度无限振动命令。

可以使用 WKScriptMessageHandlerWithReply 接收消息并返回结构化结果；原生→Web通过固定函数与编码参数传输，不拼接未经转义的字符串执行。该协议支持回复，不意味着必须等待回复再显示等级。[S2]

### 3.2 有效来源与去重

只接受当前WebView、主frame和允许的本地资源文档；握手建立新sessionId。每次重建宿主、重试与切关使用generation / attempt隔离。相同messageId重发只返回相同ACK，不重复触感或写档。future/old generation的反馈直接拒绝；版本不匹配停在可解释的启动错误页。

本地握手标识用于防误投与重放，不作为抵御设备拥有者篡改HTML的安全凭证。不会把GitHub token或商店秘密传给JS。

### 3.3 判级不能等原生

JS接受关闭后同步冻结计划并立即更新按钮与阀门；关停和余水结算完成后再更新DOM等级，向原生发送反馈和结果两条异步消息。native响应慢、失败或超时都不能改变等级或把结算后的P95≤100ms变成“等桥接”。非关键反馈超时直接丢弃，重要存档则进入有界重试与ACK流程。

不要每帧把所有水滴或V/A/O发到Swift。桥接只传离散事件、最终结果、设置和诊断摘要，避免桥接量成为渲染瓶颈。

## 04｜事件时间线与跨时钟同步

### 4.1 三条时间线不能混用

核心使用以出水为零点的timeUs；Web显示使用performance.now；原生使用单调时钟，触感引擎又有自己的currentTime。绝不能假定这些值共享原点。引擎currentTime可用于触感调度，但启动/重置后映射必须重建。[S3]

进入待机和前台恢复后发送若干clock.ping，采用最低往返样本估计Web→原生偏移并记录不确定度；再映射至当前引擎时钟。校准只用于视听触感同步，不得修正游戏关闭时刻。系统后台时间不补算成新水量。

### 4.2 一次关水的安排

| 相对关闭输入 | 行为 |
|---|---|
| 立即 | JS消耗输入、冻结关停计划，按钮与阀门开始反馈 |
| 关停与余水阶段 | 按真实事件继续流水、落水与尾滴；不显示等级 |
| 余水结算后的下一可呈现帧 | 等级可读，目标≤100ms，不等结果动画结束 |
| 原生收到关闭事件 | 当前尝试且不过期时触发短脆关闭反馈 |
| 等级动效落定，初始约200ms | 等级纹理与结果声音配合；S两次短瞬态 |
| 后续尾滴真实落地 | 优先级最低的轻触点；与其他纹理相邻则省略 |
| 新尝试 / 离开前台 | 取消旧时间线，不补播过期事件 |

关闭确认优先，关停与末滴按真实计划发生，等级只在余水结算完成后出现。计划生成一次，视觉落定时间随减少动效策略而定，再给原生相同目标；不能视觉已经消失后仍按旧动画时长发震动。

### 4.3 迟到与降级

增加工程初始目标：桥接接收延迟P95≤30ms；关闭触感的调度调用相对有效输入P95≤60ms；等级视听触感目标时差≤30ms。上述均需真机核对，软件调用时刻不是物理振动开始时刻。

超过100ms才到达的关闭反馈丢弃，不补一次迟来的“关阀”；过期等级/尾滴同理。时钟映射不可信时只保留当前关闭的即时确认、禁用复杂组合并记诊断，不延迟余水结算后的判级。恢复引擎时只为未来事件准备播放器，禁止重放历史队列。

## 05｜Core Haptics实现与反馈参数

### 5.1 一套协调器而非到处调用震动

HapticCoordinator先检查硬件能力与用户开关，缓存只读pattern并持有引擎。待机阶段预热，使用时创建/复用可取消player；Core Haptics的能力查询、停止/重置回调及模式播放器用于这条流程。[S3]

| 事件 | 参数起点 | 使用规则 |
|---|---|---|
| 开始 | 瞬态，强度0.15 / 锐度0.35 | 用户明确开始确认，不每秒敲击 |
| 材质落定 | 瞬态，0.12 / 0.20 | 正式待机前一次，接水前结束 |
| 接受关水 | 瞬态，0.35 / 0.75 | 最优先，一次有效输入只一次 |
| A/B落定 | 瞬态，0.18 / 0.30 | 仅正式关，和关闭错开 |
| S落定 | 两次瞬态，0.28 / 0.16，间隔70ms | 整体轻巧，不额外拖住下一步 |
| C/D落定 | 瞬态，0.10 / 0.20 | 中性，不惩罚式强震 |
| F落定 | 低锐度短纹理，强度0.25，≤120ms | 不猛烈震屏；不谎报真实溢出时刻 |
| 最后水滴 | 强度≤0.08 | 仅 ClosingPlan 中的真实尾滴；冲突时取消 |

0–1数值是设计参数，不是物理振幅；不同机型手感需单独评审。[D0 §09]

### 5.2 禁止泄露最佳时机

接水中不持续震动，不按水位增强，不跟99%阈值发信号。试接可以有开始、关水、材质事件，但不播放正式等级奖励纹理；其关闭反馈与正式关相同。

末滴触感仅由关闭后的真实尾滴事件触发，不能把每个落水粒子都转换为持续节拍。音频开关和触感开关独立；静音不等于允许补上一条水量震动线索。

### 5.3 引擎停止、重置与降级

stoppedHandler标记引擎不可用并停止player；resetHandler中重建player并尝试为后续操作恢复引擎。Apple指出reset回调不在主线程，相关处理应转入协调器的串行执行域。[S4]

自定义触感失败时，仅在设备支持、用户允许且事件仍新鲜时选择系统短反馈；一次事件只能走一个后端，不能Core Haptics与系统反馈同时播放。完全无触感也必须完成所有等级与关卡。

## 06｜动效实现与不透明约束

### 6.1 动画不接管游戏时钟

三维材质转场由Three.js材质参数/替换驱动；按钮和等级DOM采用transform / opacity，避免每帧重排大布局。统一FeedbackTimeline从同一事件读取目标时刻。游戏PREPARING的600ms与物理关阀时长不受动画速度影响。

| 动效 | 初始范围 | 约束 |
|---|---|---|
| 重试复位 | 180–250ms | 清掉旧水后复位，不移动模拟里的杯子 |
| 透明→不透明 | 220–350ms | 清空先完成，期间禁出水，最后进入正式待机 |
| 关闭 | 首反馈≤50ms | 操作马上响应，水按计划继续落下 |
| 等级 | 余水结算后首帧≤100ms，收束180–240ms | 字符从首帧可读，不做遮挡式揭晓 |
| S装饰 | ≤350ms | 不遮住控制区，不阻塞重试 |
| 下一关 | 250–350ms | 新容器稳定后才可开始试接 |

iOS高画质可增加近景高光、波纹层次和水痕，但正式杯内对象仍不进入绘制/反射/阴影通道。不得因为高质量焦散或新的内侧高光重新泄露水位。

### 6.2 减少动效与辅助功能

读取系统减少动态效果，实时通知Web；应用内“减少”可进一步减少，不能强制覆盖系统的减少要求。去掉非必要缩放、视差和大位移，改为短淡入或直接切态；等级仍在余水结算后立即可读，模拟规则不变。Apple的评估关注移除可能引起不适的运动，而不仅是把速度调慢。[S5]

触控热区至少44×44逻辑点，主按钮建议52点高；安全区与系统底部手势不冲突。VoiceOver可识别阶段、按钮与结果，不把内部水量作为隐藏朗读文本。该版本仍不宣称盲接玩法已经完整服务于全盲用户。

旋转设备不能让镜头升高。首版iPhone竖屏游戏，非目标布局给稳定提示；系统字体增大、显示缩放和安全区变化不能压住关水按钮或把成绩挤出画面。

## 07｜音频所有权与多模态验收

### 7.1 同一水声模型，避免双重播放

默认两端都由共享Web Audio播放流水、阀门和滴水；Core Haptics设置为只承担触感，不再播放另一套同步水声。声音模型读取同一水量 / 流量参数，透明与正式只换材质，不因“看起来陶瓷”而改变共鸣模型。

原生配置以可静音的环境音使用场景为目标，关注静音开关、锁屏、其他音乐与耳机路由；ambient类别允许混音并受静音/锁屏影响，但WKWebView和触感引擎组合后的实际行为必须真机验收，不能只检查setCategory返回成功。[S6]

若Web音频导致音频会话行为无法满足要求，再单独评审原生音频适配器。换适配器也必须保留同一声音曲线；一个构建里只能有一个音频播放所有者。

### 7.2 开始、关闭、尾滴各自结束

开始手势激活声音；关闭时源头声按计划淡出，落水与末滴按真实事件结束；等级声不覆盖关闭机械声。切后台立刻停止声音，不申请后台音频能力来持续接水。

耳机断开、蓝牙延迟或音频重置不改变核心时间。绝不为了等蓝牙声音播放而推迟视觉结果或判级。路由改变后必要时无声完成本局，下次明确操作再恢复。

### 7.3 触感测量与体验记录

软件日志记录输入、JS事件、桥接收包、引擎调用及视觉计划时刻；这只能验证调度路径。屏幕录制不能直接证明实际触感开始时刻，模拟器也无法验收振感。

真实同步使用高帧率外部拍摄配合接触式传感/加速度采集作可选客观测量；没有硬件测量设备时，用真机人工体验记录相对同步和不适反馈，并明确未量测物理起振延迟。

建议至少3名评审者在较旧、小屏及主流机型逐项评审：关闭是否清脆、等级是否落定、组合是否过密、F是否过重、连续20分钟是否疲劳。记录机型、握持方式、系统设置与参数版本。目标评分≥4/5是项目门槛，不是客观行业标准。

## 08｜原生存档、幂等和升级

### 8.1 原生是iOS持久化唯一权威

Web运行时保留内存态；通过SaveStore保存最高等级、trialCompleted、settings、latestResult、schemaVersion、revision及近期attempt摘要。iOS不依赖file URL下localStorage的持久化；那是HTML独立运行时的降级适配器，不是原生包的正式存储。[D0 §11]

SaveStore用串行actor校验和合并，再将Codable JSON写入Application Support的临时文件，成功后原子替换主档并维护上一份有效备份。结果按attemptId幂等；ACK只有在写入成功后才返回。正式等级比较 S>A>B>C>D>F，同级不隐含比较水量。

### 8.2 即时显示与保存边界分开

Web在余水结算后先出等级，再异步提交同一结果。桥接失败按有界策略重试，沿用同一messageId和attemptId，不能创建第二个成绩。结果已显示但未ACK时标记pending；超过约300ms仍失败可非阻塞提示“成绩暂未保存”，禁止谎称已经落盘。

正常切后台时优先提交待写结果并停止视听队列；ACK后的结果必须跨重启保留。若整个进程恰好在关闭输入与原生收到数据之间被强制杀死，异步桥接无法保证保存这一个结果；这属于明确的崩溃窗口，不用“升级保留”承诺掩盖。未ACK的最新局允许丢失，但不能损坏之前有效档。

验收分别测试“ACK后强杀”和“ACK前强杀”，不能把两者混为一条必定保存的用例；正常生命周期不应经常落入pending窗口。

### 8.3 迁移与恢复

同Bundle ID升级先读旧schema并迁移，保留已完成试接及历史等级。规则/关卡参数变化时提升对应版本；旧纪录附版本保留，当前规则新纪录独立，不暗清用户进度。

主档损坏先验备份；都无效则安全默认并提示，不崩溃。写入失败保留旧档和会话成绩。清除进度二次确认且不删除声音/触感偏好。不承诺卸载重装恢复，不做iCloud或跨Web同步。

## 09｜生命周期、进程与恢复状态

### 9.1 原生与Web双重监听，单一中断结果

原生监听scene失去active/进入后台，Web监听visibilitychange/pagehide；都发往同一幂等中断通道。原生无需等JS响应即可停止触感与宿主音频；JS收到后取消未结算尝试。失活期间不得模拟补帧、接满或重新开始。

| 发生节点 | 恢复结果 |
|---|---|
| 准备期/透明接水 | 本次无效，不增加已试接次数；透明待机 |
| 正式接水 | 不出等级、不改历史最高；正式待机 |
| 试接已反馈 | 完成标记保留；取消尾水，恢复试接反馈 |
| 正式已判级 | 保留已确认结果；不再播放旧等级/尾滴触感 |
| 材质转场 | 清空并落到目标待机或返回透明；不自动出水 |

### 9.2 Web内容进程终止

实现Web内容进程终止及导航失败恢复入口；WKNavigationDelegate提供相关回调。[S7] 取消原生所有旧attempt事件，递增sessionId，重新载入Bundle资源并握手。

有ACK的latestResult恢复为结果页，无结果的active attempt作废并回到对应阶段待机。不能恢复一半水继续计分。连续恢复失败显示“重新打开游戏”，限制自动重建次数，避免无限白屏循环。

### 9.3 其他异常

Core Haptics异常只降级触感；不能触发F。存档异常只提示保存限制；不能阻止当局关闭。低电量/热压力不改流量；必要时在下一局切画质。严重卡顿超过安全阈值时技术中断，不能把丢失的时间吞掉继续出成绩。

安全超时仍是核心定义的30s，不把系统挂起或进入后台算作无人关水。所有恢复动作都必须验证generation，并抛弃迟到的result动画事件；已成功落盘的历史结果不会因generation过期被删除。

## 10｜性能、设备矩阵与路线门槛

### 10.1 测试矩阵先冻结，后宣称支持

首批候选设备包含：性能较旧的iPhone（如iPhone 11）、小屏设备（如SE第三代）、一台主流高刷新率机型。具体机型、系统build、Xcode/SDK、画质、低电量模式、温度/供电条件写入执行表，不用“最新iPhone”代替记录。

| 指标 | 发布前要求 |
|---|---|
| 冷启动 | 安装后断网首次启动，20次，P95≤3s |
| 输入/等级 | 首反馈P95≤50ms；余水结算完成到等级首帧P95≤100ms |
| 渲染 | 默认目标60fps，低档30fps；不先承诺120fps |
| 触感 | 调度与体验分别测，关闭/等级/末滴没有错误重放 |
| 连续运行 | 20min且≥100次重试；观察Web进程与宿主内存、发热 |
| 公平性 | 跨Web与iOS同输入得到完全一致的整数账目和等级 |

Web进程可能单独占用资源，仅测宿主RSS不足以说明内存稳定。用Instruments及Web调试指标结合节点/纹理/几何计数观察趋势，先预热再比较，不能把缓存首次增长当作泄漏，也不能只看最后一次内存。

### 10.2 路线去留门槛

先在一杯两阶段样机上跑近满、余水结算后判级、三种结果纹理和后台恢复。如果最低目标机的低画质仍无法稳定、结算后100ms等级门槛失败或桥接振感严重滞后，先定位CPU、GPU、透明层、音频和桥接各段。

移除非必要焦散、减少像素比、缓存材质并减少桥接之后仍失败，再决定提高最低支持设备或评审独立渲染路线。不能直接降低模拟精度、改变出水曲线或漏发尾滴“优化”。

### 10.3 发布构建与权限

Debug可附固定回放和故障注入；Release移除可改级、任意执行、实时水量面板和可编辑网络地址。安装包只含固定本地内容，无广告/跟踪SDK。签名和分发前检查实际隐私声明及发行要求；本方案不保证商店审核结果。

| IOS-07 真机验收 | 性能报告、触感评审、离线、跨端金标、安装测试 |

先建立带关闭反馈的最小宿主，再做等级组合触感，不从大量动画素材开始。关闭事件的双端结果稳定后，才调整手感参数。

### 11.2 自动化层级

复用共同C-*测试，通过测试专用桥注入相同golden fixtures，读取只读快照比较；Swift单测覆盖协议、存档、调度去重和引擎后端mock。XCUITest覆盖界面、切关、重启与可访问性，设备手感由真机评审补足。

mock引擎测试只能证明某个事件被请求一次，不能证明设备真的振动、强度合适或与像素同步。桥接delay/drop/reorder、存储失败、engine reset和Web进程重建须可在QA构建独立注入；Release不暴露这些入口。

### 11.3 两端联合门禁

iOS工作簿复用与Web相同的C编号，代表同一个语义测试在另一环境重新执行，不代表Web通过后iOS自动通过。共同测试+原生专项覆盖PRD AC01–34；单文件file复制测试为Web交付专项，不当作iOS安装要求。

测试执行记录至少含build、机型/系统、前置状态、步骤、预期/实际、证据、负责人及状态。当前交付全部标记未执行。签名安装成功只说明能安装，不能替代规则、性能、隐私或离线验收。

## 12｜验收红线、风险和参考

### 12.1 不能豁免的故障

原生桥接使等级迟到、旧尝试补震、正式水位泄露、iOS有独享的最佳关水提示、跨端等级不一致、ACK后结果丢失、后台偷偷接水、必须联网才能进入六关，均为发布阻塞问题。自定义触感暂不可用允许按规则无触感降级，不能阻断游戏。

### 12.2 必须如实披露的边界

本方案仍用Web图形渲染，不承诺Metal级性能。iOS安装包不是“iPhone文件App打开HTML”的修复方式，两者为不同交付。离线指游戏内容运行，不意味着从未联网也能完成开发者签名/分发准备。

异步存档ACK前的突然进程终止可能丢失最新一局；ACK后必须保留。触感的物理起振时差须硬件测量或明确标成主观评审，不能拿函数调用时间冒充。设备兼容和审核均待实际验证。
