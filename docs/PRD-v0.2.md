# Water Fill｜满一点
## PRD v0.2 · 双阶段关卡与离线 MVP

**日期：2026-09-14｜状态：评审稿｜交付规划：单文件 HTML MVP → 网页完整版 / iOS 体验版**

> 看得见时建立判断，看不见时凭感觉关水。

每关先用透明容器反复试接，熟悉该容器和龙头；准备好后，使用同一容器的不透明呈现进行正式挑战。每次接水仅能关闭一次，余水结算后直接给出等级。iOS 在相同规则上重点打磨动效、声音与触感的协同。

### 本次已确认的变更

| 维度 | v0.2 要求 |
|---|---|
| 自由练习 | 删除独立模式、入口及其反复开关补水规则 |
| 关卡结构 | 每关内置透明试接阶段，可反复整局尝试；再进入不透明正式挑战 |

| 实施基线 | 6 关；B 及以上解锁；准备期 0.6 秒；D 为 0–80%；全部余水结算后显示等级 |

### 已确认的实施基线

MVP 做 6 关；首次进入每关至少完整试接一次，之后由玩家决定何时正式挑战；正式挑战也能反复重试；等级用 S / A / B / C / D / F，B 及以上解锁下一关；试接结算显示满杯度，正式结算只显示等级和一句反馈。准备期统一为 0.6 秒，D 级范围为无溢出的 0–80%，正式等级在全部计分余水落地后显示。

以上作为开发与验收基线，不得在实现中静默调整。关卡容量、流量、动效细节和性能目标仍须通过试玩与真机验证；如需改变基线规则，应同步更新产品、技术方案、配置版本、金标数据和验收用例。本次只更新产品规格，不代表 Demo 代码、安装包或发布状态已发生变更。

## 01｜产品定位与范围

### 1.1 核心体验

从原版“观察液面、择时关水”，调整为“先建立经验，再在信息减少时作出判断”。透明阶段不是一个额外游戏模式，而是每关的学习环节；不透明阶段是对刚刚形成的时间感、流量感和余水判断的检验。

玩家在单次接水期间仍只有一个有意义的动作：关水。开始、重试和进入正式关属于局外流程，不增加拖动、调节流量、连续点击补水或移动容器等操作。

### 1.2 版本范围

| 项目 | HTML MVP · 必须交付 | 后续网页 / iOS |
|---|---|---|
| 核心循环 | 透明试接 → 不透明挑战 → 等级 → 重试 / 下一关 | 规则一致，不能各自改变阈值 |
| 内容 | 3 种容器、2 种龙头、6 关，均有两个阶段 | 评估扩展到 6 杯、4 龙头、24 关 |
| 反馈 | 水柱、余水、溢出、基本动效、内置水声 | 更细材质、声场、iOS 原生触感 |
| 成长 | 单关最高等级、顺序解锁、会话内进度 | 持久存档与规则迁移强化 |
| 交付 | 单个离线 HTML，接收者无需安装开发工具 | 可选 HTTPS 托管；iOS 本地资源安装包 |
| 不包含 | 账号、联网榜、广告、支付、体力、云同步、独立自由练习 | 未另行评审前仍不包含 |

6 关和 24 关都是内容规模建议，不因“网页与 iOS 两版”就要求先完成两套独立代码。iOS 质量要求独立验收，HTML MVP 不冒充 iOS 正式版。

### 1.3 两个阶段必须是同一道题

容器内壁、容量、位置、喷嘴高度、源头流量、开关阀曲线、尾滴数量和水量、初始状态、脉动相位及计分规则完全一致。只改变容器的可见性和反馈层级。

透明与不透明不是换成两只声音、容量各不相同的杯子；是同一容器的观察呈现与遮蔽呈现。不得在正式关偷偷加速、缩小容量或增加余滴，也不因试接次数改变难度。

### 1.4 要验证的假设

验证玩家是否能把透明阶段学到的经验迁移到正式关，是否认为等级公平，以及是否愿意主动再次尝试。默数时间是一种合法策略，不因担心“数秒”就在正式关加入无法学习的随机性。若玩法过于机械，优先改变不同关卡的容量、流量和节奏，而不是破坏同关一致性。

### 1.5 试玩指标

建议 10–15 名未参与开发的测试者：多数能在一分钟内说明两阶段区别；至少 80% 理解同关参数不变；至少 70% 在无人提示下主动进行第二次正式尝试。记录试接次数、首次正式等级、返回学习比例和公平感评价。指标用于发现问题，不外推商业成功；离线版不声称能自动统计全体用户留存。

## 02｜完整流程与转移条件

### 2.1 首次进入一关

关卡卡片 → 透明空杯预览 → 点击“试接一次” → 0.6 秒准备 → 自动流水 → 单次关水 → 全部余水结算 → 试接反馈。

试接反馈保留透明容器与最终液面，显示“再试一次”和“进入正式挑战”。玩家可以不限次数重试，不设成绩门槛。默认至少完成一次有效试接后才开放正式挑战；试接溢出也算完整尝试，主动退出或技术中断不算。

### 2.2 进入正式挑战

点击“进入正式挑战”即表示开始意图，不再多加一层确认。系统清空本轮所有水与效果 → 将同一容器切换为不透明 → 材质与布局稳定 → 与试接相同的 0.6 秒准备 → 自动流水。

时间记忆的起点统一为源头实际开始出水，并同步给出可见开阀动作和起始水声。材质切换耗时不计入接水时间。不能在切换过程中偷偷开水，也不能携带试接余水。

### 2.3 正式局结算后

| 情况 | 主要操作 | 次要操作 |
|---|---|---|
| S / A / B | 下一关 | 再挑战一次；回到透明试接 |
| C / D / F | 再挑战一次 | 回到透明试接；返回关卡 |
| 最后一关通过 | 查看本次通关结果 | 挑战更高等级；返回关卡 |
| 技术中断 | 重新开始当前阶段 | 返回关卡 |

“再挑战一次”只重开一局不透明挑战，不强迫重做透明阶段；“回到透明试接”仍属于本关。下一关首次进入时必须回到该关的透明学习流程，不直接跳进另一只不透明杯。

### 2.4 学习记录与返回规则

每关以 levelId + rulesVersion + levelVersion 记录是否完成过透明试接。已有记录且存档可用时，重访可选择试接或直接正式挑战。影响玩法的版本变化使“已学习”标记失效；旧解锁资格保留，玩家先重新熟悉新参数。

不跨两个阶段保存进行中的半杯水。离开后回来只恢复阶段入口，不恢复正在下落的水或补算后台时间。各阶段没有主动暂停后继续本局的功能。

### 2.5 首轮体验时长目标

单次有效接水目标约 7–14 秒，关水后一般在 0.6–1.8 秒内完成余水并显示反馈。玩家试接次数不设上限，因此不能把“整关完成时长”固定成一个短动画长度。优先优化频繁重试的清空与准备，不用长转场消耗耐心。

## 03｜透明试接阶段

### 3.1 目的与信息

让玩家看清水位上升、容器截面变化、阀门关停和空中余水。画面持续标记“透明试接 · 不计正式等级”。接水时不显示秒表、实时百分比、最优停止线或人工倒计时提示，避免学习对象变成进度条。

### 3.2 交互规则

每一轮从空杯、关闭的龙头和固定初始状态开始。点击开始后自动出水；玩家单次关水，不能重新打开、点滴补水或清空后接着计算同一轮。接水中退出按放弃处理，返回本关试接入口。

反复尝试指“再来一整轮”，不是恢复 v0.1 的“开 / 暂停 / 再开 / 清空”自由操作。试接与正式局共享同一套物理结束规则：首次溢出锁定本轮溢出并关闭供水；满杯但未溢出不会提前替玩家停水。

### 3.3 试接结算

| 本轮情况 | 可见反馈 | 不应出现 |
|---|---|---|
| 未溢出 | 最终透明液面；“本次接到 98.7%”等满杯度 | 正式等级、加星、解锁 |
| 关早了 | “还可以再多一点” | 精确告诉玩家下次晚多少毫秒 |
| 发生溢出 | “溢出了，下次提前一点”；溢出比例 | 杯内“100.4%”这类超过容量的表达 |
| 关水后才溢出 | 首次提示“关水后，余水还会继续落下” | 将原因错误归为输入无响应 |

满杯度向下保留一位小数，不把未满的水显示成 100.0%。若溢出不足 0.1%，显示“少量溢出（<0.1%）”。提示用于方向性学习，不展示完整计算过程或最佳关水时刻。

### 3.4 重试与进入正式关

“再试一次”清空杯内水、空中水、源头关停余量、溢流、水痕、波纹能量、失败标记及本轮音效队列，再按同一准备时间开局。保留本关已完成试接次数，不继承随机流量状态。

“进入正式挑战”在结算或静止预览时操作，不能在试接正在出水时突然把杯子变黑继续同一局。转入正式关不会清除已取得的历史正式等级。

### 3.5 验收重点

试接次数不设上限；不同尝试的规则和初始相位相同；任何试接结果都不更新正式最高等级或解锁下一关。连按重试、移动端多指或切后台不能带入旧水滴，也不能跳过首次试接要求。

## 04｜不透明正式挑战

### 4.1 不透明的定义

正式关遮住容器内部的水位信息，而不仅是把玻璃染深一点。容器外形、位置和物理参数保持不变；材质表现可使用不透光的遮蔽层。不能用“磨砂但还能隐约看出水位”替代不透明要求。

默认正式关保留外部水柱、喷嘴、阀门和实际溢流的可见性；保留与试接一致的自然水声。水面、杯内波纹、内部气泡和水体体积不可见。外部已经发生的溢出可以看见，因为失败此时已经成立。

### 4.2 杯口与信息泄漏

只修改杯壁材质不足以保证遮蔽：俯视镜头仍可能看到杯内水面。两阶段采用同一锁定镜头，优先通过低视角和有效杯缘遮挡处理；对宽口杯型补充仅影响内部可见性的遮蔽渲染。不添加影响进水的物理盖子，不修改碰撞或容量。

| 泄漏通道 | 正式关约束 |
|---|---|
| 俯视杯口 / 横屏 | 任一支持布局都看不到内部动态水位；禁止自由旋转镜头 |
| 阴影 / 焦散 / 反射 | 不通过台面光斑高度或杯壁透光暴露内部水量 |
| 射流 / 水滴 | 进入杯缘后被正确遮挡，不透过杯壁连接隐藏液面 |
| UI / 辅助文本 | 不实时显示、播报或写入可见标签中的满杯度 |
| 画质 / 减少动效 | 降级仍保留遮蔽，不因去掉材质而露出水面 |

本项防止正常玩法中的信息泄漏，不宣称离线客户端具有防调试或防作弊能力。

### 4.3 输入与结束

自动出水后，点击主场景或“关水”按钮只接受第一次有效关闭。点击后立即锁定动作，并播放阀门关闭；已发出的水继续落下。正式局不能补水、暂停观察、实时变透明或在结算前进入试接。

首次溢出自动锁定 F 并执行关停收尾。不能依靠自动停水得到高等级。没人关水时仍按同样规则结束，另有安全超时作为兜底。

### 4.4 “直接打出等级”的含义

直接是“不要求第二次点击、不先展示长动画或分数滚动”，不是按下关水的那一刻忽略余滴立即判级。全部计分余水落地后，等级在 250 毫秒内开始出现；可伴随很短的进场动效。正常关停到结果目标 0.6–1.8 秒。

正式结果默认维持容器不透明，不先变透明揭晓水位。主信息为等级与一句话，不展示百分比、星星、1000 分和复盘按钮堆叠。玩家要重新观察时，回到本关透明试接即可。

## 05｜等级、通过与记录

### 5.1 等级替代星级主反馈

保留“越接近满杯越好、溢出失败”的原则，MVP 主界面删除 v0.1 的分数与三星体系。等级阈值为本稿建议，B 的 90% 通过线沿用此前一星通关的门槛，避免同时大幅改变难度。

设 C 为有效容量、V 为全部余水落地后的杯内保留水量、O 为累计溢出量，r = V / C。只有正式局更新等级记录。

| 等级 | 判定条件 | 结果文案 | 解锁下一关 |
|---|---|---|---|
| S | O = 0，99% ≤ r ≤ 100% | 恰到好处 | 是 |
| A | O = 0，97% ≤ r < 99% | 非常接近 | 是 |
| B | O = 0，90% ≤ r < 97% | 接得不错 | 是 |
| C | O = 0，80% ≤ r < 90% | 还能多一点 | 否 |
| D | O = 0，0 ≤ r < 80% | 关早了 | 否 |
| F | O > 0，或合法关卡无人关水达到安全上限 | 溢出了 / 没有关水 | 否 |

技术中断没有等级，不能拿 F 代替异常。S 是最高等级，不在 MVP 叠加 SSS、连击倍率或隐藏称号。实际满杯且未溢出仍为 S；不强求玩家达到精确 100%。

### 5.2 边界例子

96.2% 时关水，余水再进入 2.5%：最终 98.7%，试接显示 98.7%，正式局显示 A。98.5% 时关水，余水进入 1.9%：杯内最多 100%，溢出 0.4%，正式局显示 F。

无溢出时恰好 80% / 90% / 97% / 99% 分别为 C / B / A / S。99% 以下不得因 UI 四舍五入晋级。失败锁定后，即使液面回落或动画结束仍为 F。

### 5.3 记录策略

保存最高正式等级、相应规则版本及关卡解锁；同等级保持已有最佳等级显示，不额外暴露隐藏排名。内部可以记录 r、关水时间和溢出量用于测试，但它们不是正式结果页的默认展示内容。

重试失败不降低已取得的等级。透明试接再好也不解锁。无体力、无扣分、无“考一次就永远不能重考”的限制。MVP 全部 6 关通过后，显示每关最高等级和继续挑战入口，不汇总出另一套复杂分数。

### 5.4 调参验收

逐关扫描关闭时刻，确认存在 B / A / S 区间。建议前三关 S 的关水窗口至少 120 毫秒、其余至少 80 毫秒；不达标优先改容量和流量。这些是试玩目标，不能仅用评分范围反推并宣称已通过人工可玩性验证。

## 06｜状态机与水量规则

### 6.1 共用状态，阶段只影响呈现与写入

| 状态 | 允许行为 | 转移条件 |
|---|---|---|
| LOADING | 初始化内置资源和存档 | 成功后进入关卡入口；失败显示原因 |
| READY | 选择试接 / 正式；设置或返回 | 明确的开始意图 |
| PREPARING | 清场、材质稳定、0.6 秒准备 | 全部准备结束后开阀 |
| FILLING | 自动供水；单次关水 | 关闭输入、溢出、安全超时或中断 |
| CLOSING | 关阀、按配置继续发出余水 | 源头与预设尾滴发射完成 |
| SETTLING | 空中水落地，短暂液面稳定 | 计分水归零；进入阶段对应结果 |
| RESULT | 试接反馈或正式等级；重试 / 转阶段 | 下一次明确操作 |
| INTERRUPTED | 不判级，不累计有效尝试 | 回当前阶段 READY，不自动开水 |

stage = study / official 在每轮开始时固定。每轮使用唯一 attemptId，结果与解锁只提交一次。进入另一阶段前先结束并销毁上一轮计分状态。

### 6.2 守恒与关停

源头累计放水 S = 杯内保留 V + 空中计分水 A + 溢出 O。源头发射时增加 S 与 A，落地时将 A 转入 V 或 O。不能限制总发射量为一杯而让“不关水”自动满分。[D1]

固定时间步建议为 1/120 秒；输入采用单调时间戳映射到模拟时间。画面可不同帧率，模拟不能按“每渲染一帧加一份水”运行。同关相同关闭时刻在两阶段必须得到相同 V / O 和候选等级。

水量可采用容量百万分之一的整数单位，源头积分保留小数余量，不能每步舍入后丢水。试接和正式共享同一量化方法。没有额外“溢出 1% 仍算成功”的隐藏容差。

### 6.3 近满与溢出边界

首版只做固定、直立、开口通气、单腔容器，水柱均能进入杯口。不做倾倒、多腔气塞或容器移动。水量到高度用经校验的 V(h) 表；横截面越窄，同样流量下水位越快上升。

首次实际水量超容量即进入 O 并锁定溢出。暂不加入未满时波浪独立甩出导致失败的规则；装饰波纹与细滴不能明显跑到杯外却不计失败。计分尾滴在隐藏的正式容器内仍需正常结算，不能因不渲染而删除。

### 6.4 收尾与异常

全部计分水落地即确定结果。正式关不额外等待液面完全静止，等级在其后 250 毫秒内开始出现；透明试接可保留最多 0.35 秒稳定观察后展示反馈。关水后 2.5 秒仍无法收敛的配置或运行错误按技术中断处理，不丢弃剩余水。另设单次供水 30 秒安全上限；合法关卡应在此前接满，异常零流量与无人关水使用不同原因码。

## 07｜MVP 六关与扩展内容

### 7.1 MVP 内容

三种容器：C1 直筒杯、C2 宽矮杯、C3 上窄下宽的收口杯。每种都提供透明观察和不透明正式两种呈现，模型内壁与有效容量不因阶段改变。

两种龙头：T1 稳定细流、T2 稳定粗流。两者都保留真实关停过程与空中余水。慢关尾滴和规律脉动延后扩展，不让 MVP 同时承担全部流体与节奏机制。

| 关卡 | 容器 / 龙头 | 学习重点 | 稳态容量 / 平均流量编辑起点 |
|---|---|---|---|
| 01 | C1 / T1 | 建立开始、关闭与余水直觉 | 240 mL / 20 mL·s⁻¹ |
| 02 | C2 / T1 | 同样高度变化对应不同水量 | 280 mL / 22 mL·s⁻¹ |
| 03 | C3 / T1 | 接近收口处上升加快 | 220 mL / 20 mL·s⁻¹ |
| 04 | C1 / T2 | 熟悉杯型，换成较快水流 | 240 mL / 30 mL·s⁻¹ |
| 05 | C2 / T2 | 宽杯与较快水流的时间感 | 280 mL / 32 mL·s⁻¹ |
| 06 | C3 / T2 | 收口与较快水流的组合 | 220 mL / 28 mL·s⁻¹ |

表中数字是配置编辑起点，不是已完成的模型测量。容器尺度、内壁体积和容量需统一校验；启动、关停、飞行余水使最佳关闭时刻不等于简单的 C/Q。正式参数需通过关闭时刻扫描和试玩。

### 7.2 单关配置约束

每关将初始水量设为 0，明确喷嘴位置、初速度、开阀曲线和关停曲线。不得为统一动画方便把全部关卡自动缩放到相同接满时长；也不能只换外形却宣称最优时刻一定不同。

stage 参数不能覆盖任何物理字段；容器遮蔽、结果形式与等级写入资格属于表现和流程字段。装饰随机数独立于物理，重试使用相同的计分配置。

### 7.3 24 关扩展原则

后续可恢复原规划的上宽下窄锥形杯、腰部收窄容器和葫芦轮廓宽口瓶，并加入慢关尾滴与固定相位的规律脉动。旧版 24 关表仅作为组合素材，不直接作为本版已承诺首发清单。[D1]

每个新增关卡仍有透明试接与不透明挑战。新机制先配熟悉杯型；不要同时引入陌生容器、陌生龙头和隐性参数。新增内容必须通过不透明遮蔽验收，尤其是宽口杯的俯视可见性。

### 7.4 学习与随机性

同一关的所有尝试使用同一规则、同一启动相位与可复现出水。将来若引入种子变化，应作为明确的新挑战，并先提供与该种子一致的透明试接；MVP 不做随机正式题。

## 08｜界面与交互规格

### 8.1 页面结构

MVP 不强制单独制作大型首页。首次打开即进入第一关透明预览，顶部提供“关卡”与“设置”。复访且有有效存档时回到上次关卡入口，不能自动开始计分。

| 页面 / 状态 | 主信息 | 主要按钮 |
|---|---|---|
| 透明预览 | 第 01 关；透明试接；“先看清水，再凭感觉关水” | 试接一次 |
| 透明接水 | 透明试接；完整可见水位 | 关水 |
| 透明结果 | 最终水位；满杯度；方向性反馈 | 再试一次 / 进入正式挑战 |
| 正式准备 | 正式挑战；“同一只杯子，这次看不见水位” | 由进入正式操作自动承接准备 |
| 正式接水 | 不透明容器；不显示实时水量 | 关水 |
| 正式结果 | 大号等级；一句话；最高等级可作为小字 | 再挑战 / 下一关 / 回到透明试接 |
| 关卡选择 | 6 关缩略图；最高等级；锁定条件 | 已解锁关入口 |
| 设置 | 声音、画质、减少动效；iOS 另有触感 | 返回；清除进度需确认 |

独立“自由练习”入口、资产自由组合入口、实时开关补水按钮、旧的分数 / 星级显示均删除。不以换名“沙盒”保留同样功能。

### 8.2 关水触发

点击主场景或底部按钮使用同一个单次动作处理器。鼠标 / 触摸按首次有效 pointerdown 记录；键盘支持 Space / Enter 首次 keydown。无障碍激活走同一防重入口；按住、键盘 repeat、多指与后续 click 不能重复关水。

开始手势不能同时关水；准备期输入不缓存到出水后。菜单和系统边缘手势区域排除出主场景关水命中区。主按钮目标高度 52 个逻辑单位，其余操作命中区域至少 44 × 44，正式关不能因按压态露出实时水量。

### 8.3 防误触与可读性

结果展示至少 250 毫秒，且此前指针已抬起后才启用新一轮按钮，避免双击跨过结果。正式结果等级先出现，后续短动效不能阻塞按钮超过约 0.6 秒。静音与触感关闭时，文字与图形仍完整表达成功、失败和中断。

移动端竖屏优先，主按钮与杯子分离；桌面扩展背景而非拉伸杯子。横屏只改布局，不改容量与流量；无论布局如何变化，正式内部水位不得暴露。

## 09｜动效与声音

### 9.1 体验方向

保持已有 Demo 的干净台面、克制配色和金属龙头方向，但为透明学习与不透明正式建立清晰区别。正式挑战不是隐藏一切：杯子外轮廓、阀门动作和杯口外水柱仍需有质感。水流可见阶段和正式结果共同承担视觉吸引力。

### 9.2 动效事件表

以下时长是本项目调试起点，不是平台规定。所有计分过程以模拟为准，不能为配动画时长加水或删水。

| 事件 | HTML MVP | iOS 重点打磨 |
|---|---|---|
| 空杯准备 | 清空后轻淡入，约 150–250ms | 杯体落位与细微阻尼，约 220–350ms |
| 透明 → 不透明 | 清空后遮蔽层渐入，约 250–400ms | 同一杯轮廓保持不动，材质转变更细腻 |
| 开阀 | 阀门与第一股水同步 | 机械启动感与水柱建立的重量感 |
| 点击关水 | 按钮立即响应，阀门开始转动 | 手势确认、阀门阻尼与断流形成连续动作 |
| 余水 | 已发出水下落，不冻结、不凭空消失 | 水柱收束、断裂、末端水滴与声音同步 |
| 等级出现 | 余水结算后直接淡入 | 短促落位或轻弹性，等级先可读再完成余韵 |
| 再次挑战 | 全部清场、尽快进入准备 | 短、稳定，不重复播放长开场 |

接水计分期间不推拉镜头、不慢动作、不改变时间速度。装饰性的推近或弹性只发生在结果已确定后；默认仍优先固定镜头。

### 9.3 声音要求

至少有开阀、连续流水、随接水过程自然变化的入水声、关阀、末端滴水、溢流与等级提示。透明与正式使用相同声学映射，不能换成陶瓷材质后偷偷改变关键音色。声效仅提供自然线索，不报百分比、不在最优点“叮”一声提示关水。

MVP 音源必须内置或程序生成。音频在用户开始手势中初始化 / 恢复；浏览器可能阻止未经交互的有声音频自动播放，失败时继续无声运行，不阻止开局。[R2] 默认无背景音乐，不用音乐节拍变成强制计时辅助。

### 9.4 减少动效

支持减少动效设置，iOS 跟随系统设置并允许关闭非必要装饰。减少位移、弹跳、旋转和视差，保留读懂开关水与结果所需的变化；不得因为减少动效暴露正式杯内水位。Apple 的减少动态效果指引强调区分装饰与有意义的状态变化，不等于一律冻结全部界面。[R6]

## 10｜iOS 触感体验与同步

### 10.1 产品要求

iOS 不是简单“每次点击都震一下”。触感应让玩家感觉到阀门被关住、末滴落下和等级落定；同一事件采用一致语义，避免连续强震动。Apple 的触感指引建议与视觉、声音协同、适度使用，并允许用户关闭。[R3]

| 事件 | 触感方向 | 约束与优先级 |
|---|---|---|
| 开始供水 | 轻、短的启动确认 | iOS P0；不在准备期错误触发 |
| 玩家有效关水 | 干脆、略有机械感的单次触感 | iOS P0；与首个可见反馈同事件触发 |
| 阀门收紧 | 很短的阻尼收尾 | 精细增强；不得与关水确认叠成强烈双震 |
| 末端实际水滴 | 轻而圆润，最多 1–2 次 | iOS P0；仅在已关水后，按真实落地事件 |
| S / A 等级 | 简短、明确的正向落定感 | iOS P0；不早于等级确定 |
| B / C / D 等级 | 通过与未通过语义分开，强度克制 | iOS P0；未通过不使用成功模板 |
| F / 溢出 | 一次短促提醒 | iOS P0；首次溢出和结果不得重复惩罚性震动 |
| 重试 / 切关 | 很轻的选择确认，必要时省略 | 不因高频尝试累积疲劳 |

### 10.2 不把触感变成隐藏仪表

接水进行中默认不持续震动。不能根据内部满杯度提高振幅，不能在 90%、97%、99% 阈值或“最佳关水时机”提前给提示。关水后的水滴触感不改变决策，因为关闭已经不可撤回；这也是重点打磨余滴体验的合适时点。

未来若试验水流连续触感，只能作为可关闭的增强项，随外部可见源头流量变化，而非随隐藏液面变化。其物理与关卡难度不因触感开启而改变。

### 10.3 工程实现候选

采用原生触感层；常规操作可用系统反馈，精细阀门与水滴可评估 Core Haptics 的瞬态、连续及强度 / 锐度参数。Apple 提供相关示例，并明确需检查设备兼容性、在真机上体验，不能用模拟器代表触感验收。[R4]

渲染、音频与触感消费同一事件 ID 和时间戳。关水由输入处理器即时派发；预先排定的余滴事件可在原生侧调度。不能从 JavaScript 每帧跨桥调用一次震动，不能等待触感完成后才记录关水。

### 10.4 真机验收

优先验收点击关水、最后水滴和等级出现三个事件。应用时间戳层面的同步偏差目标不超过 30ms；实际视觉 / 听觉 / 触觉匹配另用真机录像和主观评审，不把软件调用时刻等同于硬件输出时刻。

触感可独立关闭；不支持或播放失败时无声降级，游戏继续。切后台、锁屏、退出或重试立即取消未发生事件；回来不能补播整串旧震动。连续 20 分钟验证不疲劳、不持续震动，不以“更强”代替“更细腻”。

## 11｜单文件、首次离线的 HTML MVP

### 11.1 严格交付定义

交付文件建议命名为 water-fill-mvp.html。页面、样式、Three.js、游戏代码、着色器、6 关配置、模型、材质、必要贴图和音频全部自包含。拿到文件后，首次打开和后续运行都不得下载任何必需资源。

| 项目 | 必须做到 | 不接受的替代方案 |
|---|---|---|
| 文件数量 | 一个 HTML 即可完整游玩 | 外带 assets、JS、音频目录 |
| Three.js | 固定版本内联，保留必要许可证 | CDN 脚本、在线 import map |
| 资源 | 内嵌数据、程序生成或本地解码 | 运行时 fetch 模型 / HDR / 字体 / 音频 |
| 网络 | 零主动网络请求、无遥测、无服务端依赖 | “先连一次网缓存，以后离线” |
| 接收者环境 | 可执行该 HTML 的浏览器，无 npm 或本地服务器要求 | 要求先安装 Node、启动 Vite |
| 玩法 | 两阶段、等级、六关、重试完整闭环 | 只给水流展示循环作为游戏 MVP |

不依赖 Service Worker、PWA 安装或 GitHub Pages 才获得离线能力。后续可以把同一 HTML 放到网站，但托管与账号授权不再阻塞 MVP。

### 11.2 构建与运行分开

开发时可以有模块化源代码、构建工具和包管理；最终构建必须将依赖、CSS 和全部必需资产合并到单文件。用户运行不需要构建。构建产物不保留需要外部加载的 import、worker 脚本、字体或 source map 请求。

建议未压缩 HTML 大小目标不超过 8MB；在固定验收机上首次本地打开至可操作目标不超过 3 秒。数字是预算，达到质量要求前不承诺已达成；资源变大需说明必要性和启动影响。

### 11.3 离线验收方法

在从未访问过本项目的新浏览器配置中先断网，再从本地打开文件；完成第一关透明试接、不透明评级、全部关卡与重试。网络面板不能出现应用主动发出的 HTTP / HTTPS / WebSocket 请求；再用静态扫描核对外链加载点。不能用先联网加载成功的标签页证明首次离线。

### 11.4 iPhone 的运行边界

用户此前已经遇到“文件 App 下载的 HTML 无法直接用 Safari 运行”的问题。单文件与无网络只解决资源依赖，不自动解决 iOS 的文件打开方式。本 MVP 的保证路径是经过验证、支持本地 HTML 脚本的浏览器；不承诺在 iPhone 文件预览中双击即可运行。

后续 iOS 版将 HTML / 资源打包进本地应用，并由 WKWebView 等容器加载；Apple 提供加载本地文件并限定读取范围的接口。[R5] iOS 本地加载和原生触感测试属于下一阶段，不把原生壳悄悄变成 HTML MVP 的运行依赖。

## 12｜工程契约与本地数据

### 12.1 模块边界

| 模块 | 职责 | 不得做 |
|---|---|---|
| game-core | 单次关水、物理、状态机、等级候选值 | 依赖画面是否显示水来算成绩 |
| stage-flow | 试接资格、阶段转换、正式记录 | 偷改正式关容量、流量、余滴 |
| renderer | 透明 / 遮蔽、水流、溢流、动效 | 维护另一套液面或影子分数 |
| feedback | 声音、动效事件、iOS 触感桥 | 提前透露隐藏满杯度 |
| storage | 内存进度、本地持久化、迁移 | 存储失败时阻止继续游戏 |
| offline-build | 内联全部资源、检查零外部依赖 | 将在线缓存当作离线发行 |

HTML 使用 JavaScript 与 Three.js。源代码可使用 TypeScript 后编译成单文件，但不将构建工具作为用户运行前提。iOS 默认先评估复用核心与渲染，加原生触感、生命周期和存储适配；是否采用专门封装框架不在本 PRD 中无条件锁定。

### 12.2 最小数据字段

Level：id、levelVersion、rulesVersion、containerId、capacity、V(h)、faucetId、流量曲线、开关阀曲线、喷嘴与初速度、尾滴、固定种子、前置关、最长时间。

Attempt：attemptId、levelId、stage、物理配置指纹、开始 / 关水时间、源头 S、杯内 V、空中 A、溢出 O、resultCandidate、结束原因。表现层参数与物理参数分开；两阶段的物理指纹必须相同。

Progress：schemaVersion、每关已完成试接标记及版本、正式最高等级、解锁、声音 / 画质 / 减少动效设置。iOS 增加触感设置。正式结果幂等保存，透明结果只更新学习记录。

### 12.3 file:// 存档边界

MVP 必须保证本次打开期间的进度，持久保存采用能力检测后尽力写入。MDN 明确指出 file: URL 下 localStorage 的行为未被统一规定、可能因浏览器变化，并且存储访问可能抛出异常。[R1]

读取和写入均使用异常处理；失败时保留内存进度，并提示“本次进度仅在当前打开期间保留”。不保证移动、重命名文件或换浏览器后延续存档。再次打开仍可正常玩，但可能需要从第一关重新开始；离线可运行不等于跨次存档绝不丢失。

MVP 不强制增加手动导出 / 导入进度 UI；后续如确有需要再加入。iOS 使用经过升级测试的本地持久化适配，不依赖 file: 页面存储行为来保证正式存档。

### 12.4 数据与安全范围

无登录、无远程分析、无广告 SDK、无后台上传。诊断只在设备内记录有限事件；测试者可主动导出，发行包不包含调试改分入口。纯离线客户端无法作为可信全球排行依据，后续联网成绩需另做设计。本次不执行 GitHub 写入或发布。

## 13｜性能、异常与验证目标

### 13.1 性能目标

| 指标 | HTML MVP | iOS 体验版 |
|---|---|---|
| 渲染 | 目标 60fps；低档稳定 30fps | 在声明支持的设备上重点守住稳定帧时间 |
| 输入至首次视觉反馈 | 软件测量 P95 ≤50ms | 同等目标，触感另做同步验证 |
| 正式结果开始出现 | 计分结束后 ≤250ms | 等级优先可读，不等装饰播完 |
| 关水至结果 | 正常配置约 0.6–1.8 秒 | 同物理时序，不因平台改变结果 |
| 重新准备 | 资源已加载时清场与准备衔接不拖沓 | 不反复重建场景和引擎 |
| 持续运行 | 20 分钟、100 次重试无持续资源泄漏 | 另检查发热、音频中断和触感疲劳 |
| 规则一致 | 两阶段、不同帧率、不同画质结果一致 | 与 HTML 相同输入得到相同等级 |

所有指标是待测试的项目目标。最低支持系统、机型与浏览器版本在实际技术验证后冻结，不因“Demo 可用”就宣称全面兼容。触感不能通过模拟器或浏览器截图验收。

### 13.2 画质与公平

可降低像素比、透明折射精度、阴影和装饰粒子；不可改流量、容量、关停、余滴、评分和遮蔽。自动切档尽量在两次尝试之间进行，透明与正式应保持同一档位，避免学习后突然改变画面与操作表现。

回放按固定输入时间而非真实人工点击，分别在 30 / 60 / 120fps 与两阶段比较最终 V、O、等级候选值；正式记录仅在 official 阶段写入。数值差异需在约定的最小水量单位内，且不能跨等级边界。

### 13.3 异常处理

| 情况 | 处理 |
|---|---|
| 切后台、锁屏、来电 | 未结束尝试中断、不评级；停止音频和触感；回来不补算 |
| 前台连续不可见 / 长帧超过安全预算 | 技术中断，不通过丢弃时间改变水量；下一局建议低画质 |
| 图形上下文丢失 | 中断当前轮，尝试恢复；失败显示重新打开提示 |
| 音频 / 触感失败 | 无声或无触感继续，不影响输入和判级 |
| 存档失败 | 当前游戏继续；提示仅会话保存 |
| 内置资源缺失 / 解码失败 | 在开局前明确报错，不运行空白计分局 |
| 横竖屏变化 | 正常布局重排且保持遮蔽；无法合理显示时中断，不暂停偷看 |

首次有效试接标记仅在正常完成时写入；中断不计完成。等级已保存后再发生后台事件，不能撤销或重复写入。

## 14｜功能验收 · 流程、遮蔽与评分

以下为要求，不是已执行的测试报告。逻辑边界可通过自动注入确定性输入验证，材质与遮蔽另做实际渲染检查。

| AC07 | 同配置、同关水时间，两阶段回放 | 物理指纹、最终水量与等级候选值相同 |

### 15.1 发布证据清单

HTML：单文件产物与版本、依赖许可证、零网络扫描、冷启动离线录像、两阶段回放结果、六关窗口报告、存储失败与异常恢复记录。

### 15.2 不通过的典型实现

只有正式杯壁变黑、顶部仍能看见水面；尝试关偷偷显示倒计时而正式关没有；正式点击关水就出等级导致末滴不计；HTML 外链 CDN 但称“无后端所以离线”；触感随隐藏水位越满越强；取消独立自由练习后仍保留随时暂停补水。这些均为阻塞项。

### 16.3 主要风险

隐藏水位后成为不可学习的猜测：保证同题性、明确起始信号，优化试接反馈。不透明杯让水表现丢失：保留透明学习的高品质画面，把正式关的外部水柱、关阀和结果打磨好。只剩背统一秒数：不同关卡改变真实容量与流量，但不在同关偷偷随机。

动效过长拖慢反复尝试：等级先可读，重试转场短。触感用力过猛或泄漏水位：短事件、可关闭、不随满杯度预警。单文件可离线但在 iPhone 不易打开：明确浏览器验收路径与后续本地 iOS 载体，不反复用 GitHub 授权作为前提。

### 16.4 已确认基线与试玩调优

首次每关至少一次透明试接；正式可直接重考；正式只显示等级不揭晓水量；S–F 阈值与 B 解锁；MVP 六关，均作为实施基线。试玩用于调优单关容量、流量、关停参数、动效细节和反馈文案，不默认改变核心规则；如确需改变，须同步改动流程、界面、存档、配置版本、金标和验收，不只替换文案。
