# M0 单关验证记录

> M1 已新增“正式结果透明揭晓实际水量”要求；这是下一里程碑范围，当前 M0 试玩版仍保持不透明并只显示等级。

2026-09-14，分支 `feat/m0-single-level`。对应 PRD §16 的第一个里程碑 M0，不包含 M1 六关。

## 已实现

透明试接和不透明正式挑战复用同一个 L01 核心：240mL、20mL/s、60ms 线性启动、80ms 线性关闭，无预设尾滴。两阶段均准备 600ms，首次完成试接（含溢出）后开放正式；转换清空后等待明确开始。

一次关水，不可补水；杯内、空中、溢出水量守恒，最后计分水落下后显示结果。试接显示最终比例或溢出，正式直接显示 S/A/B/C/D/F，杯子保持不透明。实际溢出自动关水并判 F。后台或超过 250ms 的长帧中断，不计等级。重试清空旧轮。

正式画面不绘制杯内水面，外部水流以杯口为终点，杯壁为实色；外部溢流水仅在实际溢出后绘制。没有实时水量文本或倒计时。

单文件内联脚本、系统字体、零第三方运行依赖，CSP 拒绝外部资源与连接。

## 本轮验证

- `node tests/core.cjs` 通过：等级边界、恰好满杯、溢出 1u、重复关闭、末滴前无结果、水量守恒、30/60/120fps 最终结果相同、无人操作自动溢出。
- `node tests/ui.cjs` 通过：模拟 DOM 中的首轮试接门槛、准备阶段、延迟结果、正式清空、重试、中断，以及静态外部依赖扫描。
- 构建成功，`git diff --check` 通过。
- 浏览器工具拒绝访问本地 file URL；未绕过安全限制。因此实际离线冷启动、截图遮蔽验证、移动布局、长按和多指真机验证尚未执行，不能将模拟 DOM 结果称为 E2E 或视觉验收通过。

## M0 实现取舍与待验收项

当前保留原 Canvas 画面，独立无 DOM 的 JavaScript 核心，用标准 Python 内联构建。M1 的 TypeScript / Three.js 路线尚未实施。

飞行采用固定 108ms 延迟，属于单关规则验证近似；尚未实现技术方案的剖面容量表、随液面改变的碰撞时间、迟到输入检查点及完整冻结 ClosingPlan 校验。输入使用处理时的单调时间，未实现事件时间戳重放。发射总量采用 BigInt 精确累计积分，最终等级不依赖帧率；落水表现仍待几何模型完善。

600ms 准备和实际余水时间独立；当前关闭后约 188ms 完成结算，未达到 PRD 的 0.6–1.8 秒收尾体验目标，需试玩后协调物理参数与产品目标，不通过延迟显示等级伪造末滴时间。

M0 不含声音、持久存档、六关解锁或 iOS 功能。后续进入 M1 前，应补齐上述物理与输入契约、真实离线和视觉验收，并确认单关节奏可理解、值得重试。本记录不将 M0 标为全部验收完成。
